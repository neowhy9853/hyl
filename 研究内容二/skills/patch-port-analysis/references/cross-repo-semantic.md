# 无共同历史的跨仓库语义迁移

模型主导“参考线索 → 目标模块 → 候选函数 → 语义对应 → 适配计划”。只围绕漏洞相关实现展开，不先通读两个仓库。仓库名、函数名、搜索得分和版本年代都只是线索，不证明对应关系。

## 输入及预算

`reference_repo` 只读；在其中解析 `reference_parent`、`reference_fix` 并读取参考补丁两侧。`target_repo` 用于查询精确 `target_ref`，实施接口的 `repo` 等于 target_repo。两侧不需要共同对象或共同祖先，不自动 fetch。可用 `target_hints` 指定初始模块范围；位置确认需要目标代码证据。

模型在开始前记录有效 `search_budget`，优先使用调用方限制；未指定时采用以下保守默认值，可经明确调整后另开一轮：

| 项目 | 默认上限 |
|---|---:|
| 目标检索轮数 | 3 |
| 每轮查询次数 | 5 |
| 每次返回的候选路径 | 30 |
| 每轮深入阅读的候选实现组 | 5 |
| 单次源码读取 | 200 行 |
| 两仓库累计读取源码 | 6000 行或 256 KiB，先到为止 |

模型维护轮数、候选、已读 revision/path/range 和累计用量；相关声明、测试及调用者也计入预算，不能用长日志或搜索片段绕开源码额度。受限检索工具限制单次返回数和大小；跨多次工具调用的累计预算由模型记录，硬资源限制由宿主环境执行。

连续两轮没有新增有效线索、达到预算或候选仍无法消歧时结束调查并返回 `blocked`。保存已查范围、剩余候选和缺失证据，说明继续分析需要的目标模块提示或预算，不自行无限扩展。搜索无结果不支持 not_affected。

## 1. 从参考修复提取线索

阅读 patch、被修复函数及必要依赖，形成 `reference_signature`：输入格式/状态、触发条件、危险操作、修复前检查、修复建立的安全条件、相关协议字段/常量/API/错误信息。保留与检索有关的线索及证据，先不展开全部调用图。

## 2. 在目标仓库定位模块

先按协议、功能域、配置入口或目标提示选择目录。需要全仓搜索时优先只返回路径列表或少量命中摘要，不把全仓源码送入模型。查询固定到目标 SHA；工作区未提交内容不能混入基线。

可直接使用 Git 工具，或可选的单次查询助手：

```bash
python3 <analysis-skill-dir>/scripts/search_code.py \
  --repo <target-repo> --repo-role target --revision <target-sha> \
  --pattern <protocol-field-or-operation> --path <subsystem-directory> \
  --max-results 30 --max-bytes 8192
```

助手仅执行模型指定的字面量搜索并返回候选文件，不提取漏洞语义、不选择下一轮、不确认映射。结果截断时改进检索词或缩小目录；不能将未返回文件当作无匹配。

## 3. 筛选少量候选实现

组合协议字段、危险 API、数据结构和错误路径等线索，先读局部命中，再读有希望候选的完整函数。为每组候选记录 `pending / rejected / confirmed`、保留或排除原因及证据。一组可包含拆分到多个函数的实现，不能仅选一个最相似函数遗漏其他危险路径。

## 4. 核对语义对应

确认至少两类独立代码证据，并逐项对照：输入来源/单位、触发条件、危险操作、数据与控制流、现有 guard、错误返回、锁/资源生命周期、构建入口。必要时逐层读取调用者、被调 helper、声明及有效 include。

记录 `semantic_mapping` 中 reference → target 的对应及不对应之处。安全条件可能需要目标侧不同实现或多位置修改。只有能解释目标仍有对应漏洞行为、且每项必要修复有实施落点时，才确认该映射；存在关键歧义则 unresolved。若目标已具备安全条件，需实际目标入口与实现证据才能 not_affected。

两侧自身历史可辅助理解代码，但跨仓库连接属于语义证据，不可写成 Git rename、parent edge 或虚构 merge-base。两侧历史摘要单独保存。

## 5. 形成计划并交接

`port_mode=cross_repo_semantic`、`strategy=semantic-adaptation`。保留检索账本、剩余候选及预算停止原因。按目标 API/结构生成 implementation_plan，并制定覆盖目标安全条件、边界、错误路径和正常行为的 validation_plan；不要求参考与目标补丁文本一致。

实施只在目标仓库隔离 worktree 进行。缺少关键目标依赖、构建接入或语义证据时不能放行。参考仓库保持只读；即使两侧路径和 SHA 恰好相同，也要核对仓库身份。
